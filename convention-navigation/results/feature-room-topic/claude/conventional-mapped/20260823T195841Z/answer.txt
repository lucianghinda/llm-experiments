- `app/models/room.rb:25` — `MAX_TOPIC_LENGTH = 120` and `validates :topic, length: { maximum: 120 }`. Nil/blank passes, so a room without a topic is valid; 121 characters fails validation and isn't saved.
- `app/controllers/rooms_controller.rb:57` — `room_params` permits `:topic` alongside `:name`. This is the shared params method, so `Rooms::Opens#create/update` and `Rooms::Closeds#create/update` all accept a topic in the same request that renames the room.
- `app/views/rooms/layouts/_form.html.erb` — a topic field under the name field in the shared room form (used by both the open and closed new/edit screens). It's gated on the same `can_administer?` check as the name field, so exactly the people who can rename a room can set its topic on the same screen; everyone else sees the topic as text. Like the name field it forces `room[topic]`/`room_topic` (otherwise the STI model name would produce `rooms_open[topic]`) and is `turbo_permanent` so switching the open/closed toggle keeps what you typed. `maxlength: 120` keeps the UI from submitting an over-long topic.

Tests added: model tests for optional and over-length topics, controller tests for setting the topic while renaming (open and closed rooms), creating with a topic, an over-length topic being rejected, and the read-only display for a non-administrator.

Full suite: 355 runs, 0 failures, 0 errors, 2 skips — the same 2 skips as before the change (baseline was 348 runs).

Two things I deliberately left alone, flag them if you want them:

- **The topic isn't displayed outside the edit screen** — not in the room header (`rooms/show/_nav`) or the sidebar. Displaying it there is a layout/design decision I didn't want to make unasked, but a topic nobody reads in the room itself is half a feature. Say the word and I'll put it in the header.
- **Over-long topics raise `ActiveRecord::RecordInvalid`** rather than re-rendering the form with an error, because the controllers use `update!`/`create!` and the codebase has no validation-error UI convention anywhere. In production that renders Rails' 422 page. It's only reachable outside the browser form (the field caps input at 120), but it isn't a friendly path.
