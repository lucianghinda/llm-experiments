# Handoff: convention-navigation — 80 trials run, answered, one follow-up left

## Goal

Test whether Rails convention-over-configuration saves an agent tokens, by
comparing campfire against a behaviour-preserving rearrangement of itself.
Claude Code and Codex CLI. **The pilot is complete and the question is
answered**; what remains is one follow-up condition and an optional second app.

## Current State

- **PR #8 open** on `experiment/convention-navigation`. Tree clean, all pushed.
- **80/80 trials run**, 16 cells at n=5, every trial passed, none aborted.
- `RESULTS.md` written; `results/` published through `sanitize.rb` (80 trials,
  800 files, campfire is MIT so raw transcripts cross whole).
- `results/tables.md` generated by `report.rb` — no number in RESULTS.md was
  typed by hand.

### The answer

**The assumption's mechanism is wrong; the cost it predicts is real.**

- **Zero-search navigation: 0/80.** No trial in either layout ever reached a
  needed file without grepping first — not even in conventional Rails where
  `app/models/room.rb` is exactly where convention says. Agents grep for
  identifiers; they do not predict paths. The scramble renames nothing, so grep
  costs the same either way.
- **Finding things is free**: locate cells came in at +4%, +1%, −10%, +0% input
  tokens, none significant. Codex issued an identical 2 calls / 1 search on both
  layouts every time.
- **Changing things costs 25–44%** on three of four write cells: codex
  test-writing +44% (p=0.032), codex cross-layer +29% (p=0.056), claude
  cross-layer +25% (p=0.151). Claude test-writing went −6% and is unexplained.
- **Sharpest result**: Claude search calls on the cross-layer task separate
  completely — `18,18,20,20,21` vs `24,25,25,26,26`, exact p=0.008.
- Interpretation: convention does not save an agent from searching. It saves it
  from searching *repeatedly*, when one change must land in five places.

### Known design error, recorded in RESULTS.md

The pre-registered sign test **could not have reached significance**: with four
tasks a perfect 4-for-4 sweep gives exact p=0.125. The primary analysis was
arithmetically incapable of clearing 0.05. Six to eight tasks would fix it. This
is stated plainly in RESULTS.md rather than papered over by leaning on per-task
p-values.

## Key Decisions

- One app in two layouts, never Rails vs another framework — comparing two apps
  confounds language, size, features and familiarity.
- Whole roots move, nothing below them: every directory under a Zeitwerk root is
  a namespace, so renaming one would rename a constant.
- `test/system/` and `lib/` deliberately do not move (see Failed Approaches).
- Prompts contain no path, no layout directory, and no word that greps to ≤3
  files **when one is a task target**. Domain words like "room" are allowed and
  necessary.
- Only successful trials count toward cost; failure rates reported separately.
  (All 80 passed, so this changed nothing — but it was the rule going in.)
- 5 repeats, not 3. Vindicated: the codex cross-layer effect read **+61% at n=3**
  and settled to **+29% at n=5**. A three-run experiment would have published
  double the real number.
- Success decided by script always; the test task mutates the rule out of the
  source and requires the agent's test to go red.

## Failed Approaches

- **Host-side verification of the scramble.** campfire's `bundle install` dies on
  a libyaml assertion (bundler 4.0.13, rails from git main). Use the container.
- **Moving `test/system` to `test/suite/browser`.** `bin/rails test` excludes
  system tests by a hardcoded path glob; moved, they stopped being excluded and
  the scrambled suite died booting a browser the container lacks. That is a
  change in which tests run, not in layout.
- **Counting grep-coupon words by file count alone.** Flagged ordinary English
  ("exactly", "able"). Tying the rule to task targets dropped the false
  positives and caught a real leak: "conversation" appears only in `Room`'s
  comment.
- **Matching targets against the whole Codex event.** It carries the command's
  output, so a `rg` that printed the path scored as arrival — dressing a search
  up as a prediction, which flatters the scrambled condition.
- **Naming mutation sites by hand.** `Rooms::ClosedsController` has its own
  `without_directs`; a correct test against it was scored vacuous. Sites are now
  found by scanning, not listed.
- **`pgrep -f run_grid.rb` as a liveness check.** It matches the monitor's own
  command line, so a dead grid reported as healthy for several minutes. Use
  `ps -ax -o command | grep -E "ruby[^|]*run_grid\.rb"`.
