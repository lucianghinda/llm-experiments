**The test:**

```ruby
test "a direct room can't be converted into a room other people can join" do
  direct = rooms(:david_and_kevin)
  participants = direct.user_ids.sort

  [ Rooms::Open, Rooms::Closed ].each do |type|
    room = Room.find(direct.id).becomes!(type)

    assert_not room.save, "a direct room was allowed to become #{type}"
    assert room.errors[:type].present?

    assert_equal "Rooms::Direct", Room.find(direct.id).type
    assert_equal participants, Room.find(direct.id).user_ids.sort
  end
end
```

It covers both ways a room becomes joinable — open admits the whole account, closed lets whoever edits it revise the roster — and asserts the consequence that actually matters, that the participant set is unchanged, not just the type column.

Mutation-checked both directions: passes on the current source, and with the validation removed it fails on the first conversion (`a direct room was allowed to become Rooms::Open`). The second test asserts a direct room can still be renamed. Without it, someone could "satisfy" the first test by making direct rooms unsaveable outright, which would break the existing rename path while leaving the suite green.
